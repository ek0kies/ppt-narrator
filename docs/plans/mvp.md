# ppt-narrator MVP Plan

## Requirement Summary

| Item | Decision |
| --- | --- |
| Business goal | Turn PPT speaker notes into reusable narration assets for event playback. |
| Input | `.pptx` with per-slide speaker notes. |
| Output | `notes.md`, `manifest.json`, per-slide audio files, and optional auto-advance PPTX copy. |
| Boundary | Do not modify the source PPTX. Do not store cloud TTS keys in the repo. |
| First success standard | A local command can extract notes from a PPTX and generate deterministic assets. |

## Scope

| Scope | Included in MVP |
| --- | --- |
| PPTX speaker note extraction | Yes |
| Markdown and JSON manifest | Yes |
| Per-slide audio contract | Yes, `.wav` files |
| Real cloud TTS | Yes, provider-based; Doubao HTTP provider is built in |
| External audio | Yes, accepts per-slide audio generated by other TTS tools |
| Narrated PPTX writing | Yes, embeds generated audio files and sets slide transition timing |
| MP4 export | No |
| FlowPilot integration | No |

## Design

| Option | Summary | Pros | Cons |
| --- | --- | --- | --- |
| A | Standard-library CLI with dry-run audio provider | Works offline, validates file contracts, low risk | Does not produce real spoken audio yet |
| B | Direct cloud TTS integration first | Closer to final user experience | Blocks on provider credentials, network, and API details |
| C | External per-slide audio input | Works with any TTS tool and keeps PPTX assembly provider-agnostic | Requires caller to produce correctly named audio files |

Recommended option: A. The first risk is PPTX note extraction and output shape, not platform integration. Real TTS can be added behind the provider interface once credentials and provider parameters are confirmed.

## Implementation Steps

| Step | Files | Change | Verification |
| --- | --- | --- | --- |
| CLI shell | `src/ppt_narrator/cli.py` | Parse input, output, dry-run options | CLI help |
| PPTX parser | `src/ppt_narrator/pptx_notes.py` | Read notes relationships and note XML | Unit tests |
| Pipeline | `src/ppt_narrator/pipeline.py` | Write notes, manifest, audio files | Unit tests |
| Audio provider | `src/ppt_narrator/tts.py`, `audio.py` | Generate silent WAV placeholders or Doubao WAV files with metadata | Unit tests and one-slide smoke |
| External audio input | `src/ppt_narrator/pipeline.py` | Load `page-001.wav/mp3/m4a` files from another TTS tool | Unit tests |
| PPTX writer | `src/ppt_narrator/pptx_writer.py` | Copy PPTX, embed audio assets, set auto-advance timings | Unit tests and zip validation |
| Documentation | `README.md`, this plan | Describe current and future behavior | Manual review |

## Open Questions

| Question | Impact | Default |
| --- | --- | --- |
| Which real TTS provider first? | Determines auth and request schema | Doubao, implemented as the first real provider |
| Output PPTX or MP4 first? | Determines next technical path | PPTX first; MP4 is out of scope |
| Need custom cloned voice? | Affects provider selection and compliance | Default to built-in Doubao voice; clone is explicit mode |
